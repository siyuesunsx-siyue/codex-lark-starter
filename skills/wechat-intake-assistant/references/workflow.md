# 归档流程与核验清单

## 1. 设定基线

- 先读取目标文件夹和索引，记录当前已有姓名、序号、文档链接、更新时间及计数。
- 初次建档时把当前已有文件作为去重基线，避免把旧附件当成新提交。
- 使用明确的起始时间/消息游标。`new messages` 之类的游标命令可能会改变其本地检查点；运行前先检查其语义，并保存任务自己的检查点。

## 2. 发现候选消息

- 只读取用户选定账号、会话和时间范围。若需扫描全部私聊/群聊，先确认工具可完整列出会话；最近会话列表只用于发现，不代表全部历史。
- 优先查看文件、文档链接、小程序分享和常见提交文字。一个提交可能是“发文件 + 随后一句说明”，应按发送者与时间关联。
- 把每个候选记录为：消息 ID（如工具提供）、会话/发送人、时间、附件名、大小/hash 或链接、工具返回的本地路径。工具不提供消息 ID 时，用稳定附件 hash + 时间作为幂等键并注明 ID 不可用。
- 忽略本人发出的空白模板和与任务无关的文件。不要仅凭宽泛关键词或泛化文件名判定提交。

## 3. 匹配名单与处理版本

- 读取当前名单，而非沿用旧快照。以正式姓名为规范名称，别名、微信昵称、文件正文姓名作为证据。
- 采用多证据匹配：会话联系人/群发送者、消息正文、附件文本、链接标题、名单别名。姓名冲突、同名、多人转发或信息不足时进入“待确认”。
- 表格/附件内容只提取识别提交人所必需的信息。若需要读取完整内容来判断，避免将隐私答案写进工作日志或外发卡片。
- 对同一成员按提交时间和实际内容去重。只有确认是更新版才替换/更新现有文档；附件内容无法判定版本先保留待确认，避免覆盖较新或完整资料。
- 在线链接受登录/权限限制时，不尝试绕过。若可确认发送者和文件标题，可创建仅含原链接与限制说明的归档页；如果用户要求只收实际附件，则改为待确认。

## 4. 归档与索引

- 文档名建议 `序号. 正式姓名`，序号按两位数展示；没有名单/序号时使用用户选定的命名方式，不自行造号。
- 文件导入/创建后，回读标题与内容摘要，确认目标文件夹位置正确。保存飞书 token/URL 和源消息/附件幂等键。
- 更新索引时按名单顺序排列已交人员，并逐项生成可点击直达链接。待交名单也显示序号与姓名。
- 计算 `已交人数` 为有效名单中有归档记录的独立成员数；`待交人数 = 有效名单人数 - 已交人数`。列表中核对首尾项、所有新增项和去重后的数量，确认两数相加等于名单总数。
- 只有归档和索引回读校验都通过，才提交本轮检查点为成功。部分失败则逐项记录可重试错误，不把未归档者计入已交。

## 5. 通知

- 仅在发生新归档/确认更新时发送，除非用户明确另作安排。
- 按已安装的飞书消息 skill 选择 Card 2.0/1.0、组件和发送身份；自聊消息写入成功未必触发手机推送，优先使用已验证能触达目标的机器人个人会话或指定群聊。
- 卡片包含本轮处理名单、累计已交/待交/总人数和索引链接。不要附上表格回答、联系方式、隐私诊断或原始附件。
- API 成功返回后记录消息 ID、发送身份、会话 ID、幂等键和发送时间。需要确认“手机是否弹出”时，必须有设备级证据，不能从 API 回执推断。

## 6. 定时任务

创建之前确认：扫描间隔、时区、监控范围、首次扫描基线、是否仅在新增时提醒、失败通知策略。优先复用现有自动化，避免重复创建。

每次运行：读取最新名单和文件夹 → 读取本地检查点 → 扫描增量 → 匹配与去重 → 归档并回读 → 更新索引并回读 → 成功写检查点 → 可选发送卡片。任何步骤失败都保留重试线索，不能提前标记为已完成。

周期性扫描如果依赖本地电脑，电脑关机、微信退出或授权过期时可能无法运行；向用户说明实际运行条件。调度器的回执只能证明调度结果，不能证明手机推送或微信已同步。

## 7. 完成回报

简洁说明扫描的时间范围和会话范围、新归档/更新的规范姓名及数量、当前已交/待交人数、索引位置、通知回执，以及待确认/失败项。不要在回报中重复学生敏感答案。
